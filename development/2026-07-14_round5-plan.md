# Round-5 plan — code quality & user-friendliness

Round 4 is **finished** (see [2026-07-13_round4-plan.md](2026-07-13_round4-plan.md)):
all capability items (uncertainty, DoD completion, DST reproduction,
OperationalData) landed and merged, versioned `0.1.0`. The only round-4 item
left is **B3 (new Streamlit apps)**, which is deferred pending an app spec.

Round 5 shifts from capability to **quality and usability**: make the codebase
clean and consistent, prune what's now redundant, and give users first-class
documentation and interactive learning material. Tracked as GitHub issues.

## Items

### R5-1 — Ruff linting + CI gate `[done — PR #32]` (issue #33)
Adopt `ruff`: dev dependency, curated low-noise config in `pyproject`
(`E4/E7/E9,F,W,I,B,UP,SIM`), fix all findings, and a `ruff` CI job running
`uv run ruff check .` on every PR. Behaviour-preserving; suite stayed green
(281 passed). Modernized type hints to py3.12 syntax and fixed a latent
`callable`-as-type annotation (now `collections.abc.Callable`).

Possible follow-ups: tighten the ruleset (docstring rules `D`, `B028`
stacklevel), or add `ruff format`.

### R5-2 — Redundant-file audit `[needs owner decision]` (issue #34)
Candidates now superseded by the test suite / uv packaging:
- `dev_requirements.txt` (duplicates the `dev` dependency group),
- `environment.yml` (conda, superseded by uv),
- `scripts/checks/*.py` + `scripts/check_fitting.py` + `scripts/check_simulations.py`
  (manual sanity checks, now covered by tests),
- `notebooks/parameters/.gitkeep` (leftover after the notebooks moved to
  `legacy/`).

Kept deliberately: `apps/` (reference until B3), `legacy/` (frozen reference),
`get_example_params_from_original_repo` (used by tests). Removal happens once
the owner confirms.

### R5-3 — Documentation site with Zensical `[planned]` (issue #35)
A browsable, versioned docs site built with Zensical: overview, install,
the two workflows (fit; predict), units convention, API reference, and the
fitting architecture (folding in the existing `docs/` material). CI build +
optional Pages deploy. Kept in sync with the public API and the test-executed
example so it can't drift.

### R5-4 — Marimo notebooks `[planned]` (issue #36)
Several reactive `marimo` notebooks that serve as both tutorials and tools:
quickstart tour, fitting walkthrough, DoD/chemistry, field-data prediction,
and uncertainty. Added as an optional extra (not a runtime dep), stored as
git-friendly `.py`, runnable against the public API, and linked from the docs.

## Suggested order

1. **R5-1 ruff** (done) — clean baseline first.
2. **R5-2 redundant-file audit** — quick, once the owner confirms.
3. **R5-3 docs** and **R5-4 notebooks** in parallel — they reinforce each
   other (reference docs + learn-by-doing). Sequence the docs scaffold first so
   the notebooks have a home to link into.
