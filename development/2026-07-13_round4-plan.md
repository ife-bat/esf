# Round-4 plan — further improvements

Planning pass after the DoD reference-fit landed (PR #21) and the Round-1..3
cleanup completed. The library is now: installable, CI-guarded on three
platforms, ~180 tests, all fitting stages implemented (calendar SEI, rates,
SoC/T/time/DoD stress factors) and numerically pinned, plotting extracted, a
public API, and an architecture document.

Round 4 shifts from cleanup to **capability**. Items are grouped by whether
they can start now or need owner input, and ordered by value/effort.

## A. Ready to build now

### A1. Uncertainty propagation `[Tier 0 + Tier 1 done 2026-07-13]`
The big one. Full design in
[uncertainty-propagation-design.md](uncertainty-propagation-design.md).
**Tier 0** (`fit.parameter_uncertainty()` captures the lmfit covariance) and
**Tier 1** (`esf/uncertainty.py`: `ParameterUncertainty` / `ParameterEnsemble`
/ `simulate_with_uncertainty` — sample the covariance, run the float simulator
K times, return quantile bands) are implemented and exported;
`tests/test_uncertainty.py` (16 tests) pins them, including a sampler
cross-check against first-order propagation. Non-invasive: the simulators stay
float-only; uncertainty is opt-in. **Remaining:** Tier 2 (bootstrap the staged
fit, as the reference) and per-point measurement-noise handling.

### A2. `deg_at_eol` vs `full_degradation_level` reconciliation `[done 2026-07-13]`
The DoD work surfaced that `deg_at_eol = 0.188` and
`full_degradation_level = 0.20` coexisted and disagreed. Resolved: `deg_at_eol`
was a vestigial, never-computed field — removed (PR #23, commit 59194c6).
`full_degradation_level = 0.20` (80% SoH) is the single EOL loss the DoD fit
uses. Old parameter files that still carry `deg_at_eol` load fine (the stale
key is dropped with a warning), pinned by
`tests/test_parameters.py::test_removed_deg_at_eol_key_still_loads`. If a
distinct "EOL definition" value is ever needed it is easy to add back
deliberately.

### A3. Fits return results instead of mutating `prms` (F2 finish) `[done 2026-07-13]`
Every fit facade (`sei_fit_at_reference_conditions`,
`soc`/`temperature`/`dod_stress_factor_fit`, `time_stress_factor_calc`) and
`BaseFit.fit()` now take `apply=True` (default). With `apply=False` the fit
runs but leaves `prms` untouched (not even `mark_changed()`); the result is
read via `fitted_parameters()` / `parameter_uncertainty()`. `tests/test_fit_apply.py`.

### A4. Regime as `Regime` enum end to end (F4 finish) `[done 2026-07-13]`
`coerce_regime()` normalizes any regime (enum or decorated string) to a
`Regime` enum; `BaseProcessor.regime` is now a property whose setter coerces,
so every fit stores the enum. `is_cycling`/`is_calendar` are `is` comparisons
against it. `NonlinearMultiFit` (not a `BaseProcessor`) coerces explicitly.
`tests/test_fit_regime.py`.

### A5. `OperationalData` implementation `[done 2026-07-14]`
Was a docstring-only stub; now a working input class for *prediction* from real
field data. `OperationalData.from_field_dataframe` ingests a raw trace
(SoC/C-rate/T/SoH over time, with a configurable `column_map`), converts it to
the internal units (time→seconds from a numeric column or parsed timestamps,
temperature→kelvin, SoC/SoH→fraction, C-rate unchanged), and `to_drive_cycle()`
/ `predict()` hand it to `drive_cycle_degradation_calculator`; `measured_soh()`
exposes the measured curve for validation. Exported as `esf.OperationalData`;
`tests/test_operational_data.py` (12 tests). Fixed a latent base-class bug in
passing (`Data(data=frame)` raised on a real DataFrame via `data or ...`). The
ingestion API is intentionally minimal and may grow with the B3 apps (still on
hold), but the ingest→normalize→predict core is what any app needs regardless.

## B. Needs owner input / external material

### B1. DoD fit completion `[done 2026-07-14]`
Both follow-ups to the reference-path fit are implemented (formulation
confirmed against Xu et al. via the decision record):
- **Non-reference path `[done]`** — the stress-factor-removal procedure (Xu et
  al. eqs. 20/31, decision 5). `DoDSFfit.preprocess_degradation_rates` now
  handles `is_at_reference=False`: `f_d,1 = full_degradation_level / N`, then
  `S_dod = f_d,1 / (S_T·S_soc) − S_t`, where S_T/S_soc are the cycling
  temperature/SoC models and S_t the calendar time model (so those stages must
  be fitted first). Input schema `DOD_NON_REFERENCE_COLUMNS = ("T", "SoC",
  "t_cycle")`; missing columns raise a clear `ValueError`. Synthetic
  eq-20-forward → eq-31-invert round-trip recovers the LMO constants exactly
  (`tests/test_dod_fit.py::TestNonReferencePath`).
- **Chemistry-driven model selection (decision 6) `[done]`** — new
  `quadratic_dod_k_relation` (Xu eq. 30, `k_1·δ^k_2`) registered as
  `("Cycling","dod","Quadratic")`; `ESFParams.__post_init__` resolves
  `dod_cycling_model` from `battery_chemistry`
  (LMO→Empirical, LFP→Exponential, NMC→Quadratic; unknown→Empirical) unless the
  user sets a label explicitly. NMC quadratic recovers the real NMC cycle-life
  data at R²>0.999 and round-trips synthetic data
  (`tests/test_dod_fit.py::TestNMCQuadratic`, `TestChemistryModelSelection`).

  Not done (deferred, low value): a dedicated LFP-exponential recovery test
  against `cycle_nb_at_80_SoH_LFP.csv` — the exponential form already existed;
  only the selection wiring for non-reference *field* data (through the io
  selectors) remains, which is coupled to A5 `OperationalData`.

### B2. Reproduce the original publication results `[done 2026-07-14]`
End-to-end regression against the paper's Fig. 5b (*Reproduced DST Data*): the
`DSTCycleDeg` simulator run with the paper's Table I constants
(`get_example_params`) reproduces all seven published DST curves — six of seven
final SoH values within ±0.5 pp, the deepest-DoD case (100-25) within 2.4 pp.
Reference numbers (read off the figures the owner supplied) and the acceptance
tolerance are recorded in
[dst-reproduction-reference.md](dst-reproduction-reference.md);
`tests/test_dst_reproduction.py` pins the reproduction (±3 pp vs figure), a
tight drift guard (±0.3 pp vs the current simulator), and the curve structure
(starts at 100 %, monotone, correct rank order, dataset x-extent). Established
along the way: `get_example_params()` (Table I) is the reproduction config, not
`get_example_params_from_original_repo()` (5–10 pp low), and the `high_soc`
factor is inactive in these windows.
